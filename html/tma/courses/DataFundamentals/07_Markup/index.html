1. What is a Markup Language

1.1 Definition

Markup Language — a system for annotating text where markup is syntactically distinguishable from content.

<p>This is <strong>important</strong> text.</p>

Here:

  • <p>, <strong> — markup (tags)
  • "This is important text." — content

1.2 Types of Markup

Type Example Purpose
Presentational HTML Defines display
Descriptive DocBook Describes structure
Procedural TeX Processing instructions
Lightweight Markdown Ease of writing

🧬 In Bioinformatics:

Documentation Markdown README, protocols, analysis reports
Web interfaces HTML Galaxy, UCSC Genome Browser
Publications LaTeX Scientific papers

2. HTML

2.1 HTML Basics

HTML (HyperText Markup Language) — the standard language for web pages.

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>My Page</title>
</head>
<body>
    <h1>Hello, World!</h1>
    <p>This is a paragraph.</p>
</body>
</html>

2.2 Document Structure

<!DOCTYPE html>          ← Document type declaration
<html>                   ← Root element
├── <head>              ← Metadata
│   ├── <meta>          ← Encoding, viewport
│   ├── <title>         ← Tab title
│   └── <link>          ← Styles, icons
└── <body>              ← Visible content
    ├── <header>        ← Header
    ├── <main>          ← Main content
    └── <footer>        ← Footer

3. XML

3.1 What is XML

XML (eXtensible Markup Language) — a universal format for structured data.

<?xml version="1.0" encoding="UTF-8"?>
<library>
    <book id="1">
        <title>The Pragmatic Programmer</title>
        <author>David Thomas</author>
        <year>2019</year>
    </book>
    <book id="2">
        <title>Clean Code</title>
        <author>Robert C. Martin</author>
        <year>2008</year>
    </book>
</library>

3.2 XML vs HTML

Aspect XML HTML
Tags Arbitrary Predefined
Tag closing Mandatory Sometimes optional
Case sensitivity Sensitive Insensitive
Purpose Data Display
Validation DTD, XSD Loose

3.3 XML Rules

<!-- 1. One root element -->
<root>
    <child>Content</child>
</root>

<!-- 2. Tags must be closed -->
<element>text</element>
<empty-element />

<!-- 3. Case matters -->
<Tag>Not same as</tag>  <!-- ERROR! -->

<!-- 4. Proper nesting -->
<a><b></b></a>  <!-- OK -->
<a><b></a></b>  <!-- ERROR! -->

<!-- 5. Attributes in quotes -->
<element attr="value">

<!-- 6. Special characters -->
&lt;   <!-- < -->
&gt;   <!-- > -->
&amp;  <!-- & -->
&apos; <!-- ' -->
&quot; <!-- " -->

3.5 XML in Python

import xml.etree.ElementTree as ET

# Parsing XML
xml_string = """
<users>
    <user id="1">
        <name>Alice</name>
        <email>alice@example.com</email>
    </user>
</users>
"""

root = ET.fromstring(xml_string)

# Navigation
for user in root.findall('user'):
    name = user.find('name').text
    email = user.find('email').text
    user_id = user.get('id')
    print(f"{name} ({user_id}): {email}")

# Creating XML
root = ET.Element('books')
book = ET.SubElement(root, 'book')
ET.SubElement(book, 'title').text = 'Python Guide'

xml_str = ET.tostring(root, encoding='unicode')
print(xml_str)

🧬 Bioinformatics Example:

import xml.etree.ElementTree as ET

# Parse gene annotation XML
xml_data = """
<genes>
    <gene id="ENSG00000139618">
        <name>BRCA2</name>
        <chromosome>13</chromosome>
        <start>32889611</start>
        <end>32973805</end>
    </gene>
</genes>
"""

root = ET.fromstring(xml_data)

# Extract gene information
for gene in root.findall('gene'):
    gene_id = gene.get('id')
    name = gene.find('name').text
    chrom = gene.find('chromosome').text
    start = int(gene.find('start').text)
    end = int(gene.find('end').text)
    length = end - start

    print(f"{name} ({gene_id})")
    print(f"  Location: chr{chrom}:{start}-{end}")
    print(f"  Length: {length:,} bp")

4. Markdown

4.1 What is Markdown

Markdown — a lightweight markup language for formatting text.

  • Created by John Gruber in 2004
  • Readable as plain text
  • Easily converts to HTML
  • Standard for documentation (GitHub, GitLab, Stack Overflow)

🧬 In Bioinformatics:

  • README files for pipelines and tools
  • Analysis protocols and methods
  • Lab notebooks and experimental notes
  • GitHub/GitLab project documentation
  • Jupyter Notebook markdown cells

🧬 Bioinformatics Example (Protocol):

# RNA-Seq Data Analysis Protocol

## Overview

This protocol describes the standard RNA-Seq analysis pipeline for differential gene expression.

## Prerequisites

- Raw FASTQ files (paired-end)
- Reference genome (GRCh38)
- Gene annotation (GENCODE v42)

## Steps

### 1. Quality Control

Run FastQC on raw reads:

```bash
fastqc -t 4 sample_R1.fastq.gz sample_R2.fastq.gz

Expected output: - Per base sequence quality > Q30 - No adapter contamination

2. Read Alignment

Align reads using STAR:

STAR --runThreadN 8 \
     --genomeDir /data/star_index \
     --readFilesIn sample_R1.fastq.gz sample_R2.fastq.gz \
     --outFileNamePrefix sample_

Parameters: - --runThreadN 8: Use 8 CPU threads - --genomeDir: Path to STAR index - --readFilesIn: Input FASTQ files

3. Gene Quantification

Count reads per gene using featureCounts:

featureCounts -T 4 -p -t exon -g gene_id \
              -a gencode.v42.gtf \
              -o counts.txt \
              sample_Aligned.out.bam

Quality Metrics

Metric Threshold Interpretation
Total reads > 20M Adequate depth
Mapping rate > 85% Good alignment
Duplicate rate < 30% Acceptable

References

  • Dobin et al. (2013). STAR: ultrafast universal RNA-seq aligner. Bioinformatics.
  • Love et al. (2014). Moderated estimation of fold change and dispersion for RNA-seq data with DESeq2. Genome Biology.

Author: Bioinformatics Core
Date: 2024-01-15
Version: 2.1.0

5. Format Comparison

5.1 When to Use

Format When to Use
HTML Web pages, email templates, analysis reports
XML Configurations (legacy), data exchange, SBML, GFF
Markdown Documentation, README, protocols, lab notebooks
JSON APIs, modern configurations, metadata
YAML Pipelines (Snakemake), Conda environments

🧬 Bioinformatics Specific:

Format Use Case Example
Markdown Tool documentation README.md, protocols
HTML Analysis reports MultiQC, FastQC reports
XML Legacy formats GFF3, SBML, BioPAX
JSON Modern APIs Ensembl REST, NCBI E-utilities
YAML Pipeline configs Snakemake, Nextflow

5.2 Readability vs Functionality

Simplicity          Power
←─────────────────────────────→
Markdown  HTML  XML  LaTeX

5.3 Format Conversion

# Markdown → HTML
pandoc input.md -o output.html

# HTML → Markdown
pandoc input.html -o output.md

# XML → JSON (with xq)
xq '.' input.xml

# Markdown → PDF
pandoc input.md -o output.pdf

7. Common Pitfalls

7.1 HTML: Unclosed Tags

❌ Error:

<p>Paragraph without closing tag
<div>Another element

✅ Correct:

<p>Paragraph with closing tag</p>
<div>Another element</div>

7.2 XML: Tag Case

❌ Error:

<User>
    <Name>Alice</name>
</user>

✅ Correct:

<user>
    <name>Alice</name>
</user>

7.3 Markdown: Spaces for Line Breaks

Line 1
Line 2 (will be on the same line!)

Line 1  
Line 2 (two spaces at end = <br>)

Line 1

Line 2 (empty line = new paragraph)

💡 Key Takeaways

  • HTML — for the web: Semantic tags, attributes, forms, analysis reports.

  • XML — strict format: Mandatory tag closing, case-sensitive, legacy bioinformatics formats.

  • Markdown — for humans: Simple syntax, excellent for documentation and protocols.

  • Choose format: HTML for display, XML for data (legacy), Markdown for documents.

  • 🧬 Bioinformatics: Markdown for documentation, HTML for reports, XML for legacy formats (GFF, SBML).

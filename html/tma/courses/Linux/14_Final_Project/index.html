Project Overview

Build a production-ready ETL pipeline that processes a 5GB dataset using Unix command-line tools and Python.

Requirements

1. Data Source

Choose one: - Public API (e.g., GitHub API, OpenWeather, JSONPlaceholder) - Large CSV dataset (e.g., Kaggle datasets) - Web scraping (with permission) - Simulated data generation

2. Pipeline Components

Extract

  • Fetch data from API or file
  • Handle pagination if applicable
  • Store raw data in JSONL or CSV format
  • Include error handling and retries

Transform

  • Clean data (remove nulls, duplicates)
  • Filter relevant records
  • Enrich data (join with lookup tables)
  • Convert formats (JSON → CSV, etc.)
  • Aggregate statistics

Load

  • Generate markdown report
  • Create CSV summary files
  • Optionally: Load to database (SQLite)

3. Technical Requirements

Must include: - [ ] At least 3 distinct processing stages - [ ] Parallel processing (GNU parallel or xargs -P) - [ ] Error handling (set -euo pipefail, trap) - [ ] Progress monitoring (pv) - [ ] Temporary file management (mktemp) - [ ] Checkpoints for resumability - [ ] Makefile for orchestration - [ ] Logging to file - [ ] Configuration via .env - [ ] Performance profiling (time command)

Must use at least 5 of these tools: - grep, sed, awk - jq, mlr, csvkit - sort, uniq, cut, paste - curl, wget - gzip, zcat - Python (for complex logic)

4. Performance Goals

  • Process 5GB of data
  • Complete in under 30 minutes
  • Use < 2GB RAM
  • Utilize multiple CPU cores

5. Documentation

Create README.md with: - Project overview - Data source description - Pipeline architecture diagram - Installation instructions - Usage examples - Performance benchmarks - Known limitations

Detailed Evaluation Framework

1. Functionality Assessment (40 points)

Core Pipeline Operations: - Does the extraction component successfully pull data from multiple sources? - Are transformations applied correctly with proper data validation? - Does the loading component generate all required outputs? - Is the pipeline orchestration working end-to-end?

Data Quality Verification: - Are data integrity checks implemented and working? - Does the pipeline handle missing, malformed, and duplicate data correctly? - Are business rules applied consistently across the dataset? - Is data lineage properly tracked and documented?

Error Handling and Recovery: - How gracefully does the pipeline handle various failure scenarios? - Are appropriate error messages and logging provided? - Can the pipeline recover from partial failures? - Is retry logic implemented for transient failures?

2. Performance Evaluation (20 points)

Processing Efficiency: - Does the pipeline process 5GB+ data within reasonable time limits? - Is memory usage optimized for large datasets? - Are parallel processing capabilities utilized effectively? - Is I/O performance optimized for the target hardware?

Scalability Assessment: - How does performance scale with increasing data volumes? - Are resource bottlenecks identified and addressed? - Is the architecture suitable for production workloads? - Are caching and optimization strategies implemented?

Benchmarking Criteria: - Processing throughput (GB/hour) - Memory efficiency (peak usage vs. data size) - CPU utilization patterns - Storage optimization (compression, indexing)

3. Code Quality Analysis (20 points)

Code Organization and Structure: - Is the codebase well-organized with clear separation of concerns? - Are modules and functions appropriately sized and focused? - Is there evidence of good software engineering practices? - Are coding standards consistently applied?

Maintainability Factors: - Code readability and self-documenting practices - Appropriate use of comments and docstrings - Modular design enabling easy testing and debugging - Configuration management and environment separation

Testing Coverage: - Unit tests for core processing functions - Integration tests for pipeline components - End-to-end tests for complete workflows - Performance and load testing implementations

4. Documentation Quality (20 points)

Technical Documentation: - Architecture overview with clear data flow diagrams - API documentation for custom components - Configuration and deployment procedures - Troubleshooting guides and common issues

User Documentation: - Clear installation and setup instructions - Usage examples and command references - Performance tuning recommendations - Operational procedures and monitoring guides

Project Management: - README with comprehensive project overview - Change log and version history - Contribution guidelines and development setup - License and dependency information

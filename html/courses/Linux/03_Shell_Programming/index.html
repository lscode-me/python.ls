Shell Programming as a Mini-DSL for Data Processing

Introduction

Bash isn't just a command interpreter — it's a powerful programming language designed for text processing and pipeline orchestration. When used correctly, shell scripts become a domain-specific language (DSL) for data transformation.

In this module, we'll learn to write safe, efficient data-processing scripts that leverage the full power of the shell.

Command Substitution

Command substitution allows you to capture the output of a command and use it as a value.

Modern Syntax: $(...)

# Capture command output
current_date=$(date +%Y-%m-%d)
echo "Today is $current_date"

# Use in pipelines
total_lines=$(cat data.csv | wc -l)
echo "File has $total_lines lines"

# Nested substitution
files_count=$(ls -1 $(pwd) | wc -l)

# In arithmetic
age=$((2024 - $(date +%Y)))

Old Syntax: Backticks (avoid)

# Old style - harder to nest
result=`command`

# Prefer $(...) instead
result=$(command)

Streaming Loops: while read

The while read loop processes data line by line, perfect for streaming large files without loading everything into memory.

Basic Pattern

# Read from file
while read line; do
    echo "Processing: $line"
done < data.txt

# Read from pipe
cat data.txt | while read line; do
    process "$line"
done

# Read multiple fields
while IFS=',' read col1 col2 col3; do
    echo "$col1: $col2 = $col3"
done < data.csv

Practical Examples

Example 1: Calculate average

#!/bin/bash
sum=0
count=0

while read value; do
    sum=$((sum + value))
    count=$((count + 1))
done < numbers.txt

average=$(echo "scale=2; $sum / $count" | bc)
echo "Average: $average"

Example 2: Filter and transform CSV

#!/bin/bash
# Extract high-value transactions

while IFS=',' read date amount category; do
    if [[ $amount -gt 100 ]]; then
        printf "%s\t%s\t%s\n" "$date" "$amount" "$category"
    fi
done < transactions.csv

Example 3: JSONL to CSV

#!/bin/bash
# Convert JSON Lines to CSV

echo "name,age,city"
while read line; do
    name=$(echo "$line" | jq -r '.name')
    age=$(echo "$line" | jq -r '.age')
    city=$(echo "$line" | jq -r '.city')
    echo "$name,$age,$city"
done < data.jsonl

Arrays, Strings, and Arithmetic

Arrays

# Declare array
fruits=("apple" "banana" "cherry")

# Access elements
echo "${fruits[0]}"  # apple
echo "${fruits[@]}"  # all elements
echo "${#fruits[@]}" # length

# Add elements
fruits+=("date")

# Loop through array
for fruit in "${fruits[@]}"; do
    echo "$fruit"
done

# Read into array
mapfile -t lines < data.txt
echo "${lines[@]}"
# or
readarray -t lines < data.txt

Note: mapfile/readarray loads the entire file into an array, which is convenient for small files but not suitable for large datasets, where streaming with while read is preferred.

String Operations

text="Hello, World!"

# Length
echo "${#text}"  # 13

# Substring
echo "${text:0:5}"  # Hello
echo "${text:7}"    # World!

# Replace
echo "${text/World/Bash}"  # Hello, Bash!
echo "${text//o/0}"        # Hell0, W0rld!

# Case conversion
echo "${text^^}"  # HELLO, WORLD!
echo "${text,,}"  # hello, world!

# Check if a string contains a substring (using [[ ]] for pattern matching)
if [[ "$text" == *"World"* ]]; then
    echo "Found!"
fi

# Trim whitespace
text="  data  "
trimmed="${text#"${text%%[![:space:]]*}"}"
trimmed="${trimmed%"${trimmed##*[![:space:]]}"}"

Arithmetic

Bash uses double parentheses (( )) for arithmetic that clearly separates math expressions from regular shell constructs.

# Arithmetic expansion
x=5
y=3
echo $((x + y))    # 8
echo $((x * y))    # 15
echo $((x ** y))   # 125 (power)

# Increment/decrement
((x++))
((y--))
((x += 10))

# Comparison in arithmetic context
if ((x > y)); then
    echo "x is greater"
fi

# Floating-point calculation with bc
result=$(echo "scale=2; 10 / 3" | bc)
echo "$result"  # 3.33

# Random numbers
random=$((RANDOM % 100))  # 0-99

Note: $(( )) performs integer arithmetic only; floating-point calculations require external tools such as bc.

Functions

Basic Functions

Bash functions accept positional arguments ($1, $2, etc.) and produce results via output (stdout) or variable changes — not through return, which only sets an exit code.

# Define function
greet() {
    echo "Hello, $1!"
}

# Call function
greet "Alice"  # Hello, Alice!

# Function with return value
add() {
    local result=$(($1 + $2))
    echo "$result"
}

sum=$(add 5 3)
echo "Sum: $sum"

# Function with multiple outputs
stats() {
    local sum=0
    local count=0

    while read num; do
        sum=$((sum + num))
        count=$((count + 1))
    done

    echo "$sum $count"
}

# Pass command output to read as if it were a file
read sum count < <(seq 1 10 | stats)
echo "Sum: $sum, Count: $count"

Local Variables

The local keyword restricts a variable to the function's scope, preventing accidental modification of global variables.

process_data() {
    local input_file="$1"
    local output_file="$2"
    local temp_file=$(mktemp)

    # Process data — apply any transformation (e.g., uppercase, filtering, formatting)
    cat "$input_file" | transform > "$temp_file"
    mv "$temp_file" "$output_file"
}

Exit Codes and Error Handling

Every command in Bash returns an exit code. Exit code 0 indicates success; any non-zero exit code represents a specific type of failure. Exit codes allow scripts to detect errors and react accordingly.

Exit Codes

# $? checks the exit code of the last executed command
ls /nonexistent
echo $?  # Non-zero indicates error

# Successful command
ls /tmp
echo $?  # 0 indicates success

# Set exit code in script
exit 0  # Success
exit 1  # Error

Conditional Execution

# Run command2 only if command1 succeeded (exit code 0)
command1 && command2

# Run command2 only if command1 failed (non-zero exit code)
command1 || command2

# Chain conditionally
command1 && command2 || command3

# Multiple conditions
if command1 && command2; then
    echo "Both succeeded"
fi

Useful Test Operators

# String tests
[[ -z "$var" ]]    # True if var is empty or unset
[[ -n "$var" ]]    # True if var is non-empty

# File tests
[[ -f "$file" ]]   # True if file exists and is a regular file
[[ -d "$dir" ]]    # True if directory exists

# String comparison
[[ "$a" == "$b" ]] # True if strings are equal

Here Documents

Here documents (<<) provide multi-line input to a command inline, without a separate file:

# Multi-line input to a command
cat <<EOF
Hello, $USER!
Today is $(date +%Y-%m-%d).
EOF

# Quoted delimiter disables variable expansion
cat <<'EOF'
This $variable is not expanded.
EOF

# Here string (single line)
grep "error" <<< "no error here"

Error Handling with set

The set builtin modifies the shell's behavior; the -e, -u, and -o pipefail options enable stricter error handling to stop scripts early when something goes wrong.

#!/bin/bash

# Exit on error
set -e

# Exit on undefined variable
set -u

# Fail on pipe errors
set -o pipefail

# Combine all (recommended)
set -euo pipefail

# Now any error stops the script
curl https://api.example.com/data | jq '.results[]' | process

Custom Error Handling

#!/bin/bash
set -euo pipefail

error_exit() {
    echo "ERROR: $1" >&2
    exit 1
}

# Use in script
[ -f "data.csv" ] || error_exit "data.csv not found"

# With cleanup
cleanup() {
    rm -f "$temp_file"
}

trap cleanup EXIT

temp_file=$(mktemp)
process_data "$temp_file" || error_exit "Processing failed"

Process Substitution

Process substitution creates temporary named pipes for command output, allowing you to use command output as if it were a file.

Syntax

# Output as file: <(command)
# Input as file: >(command)

Reading from Process Substitution

# Compare outputs of two commands
diff <(ls dir1) <(ls dir2)

# Use command output as file
while read line; do
    echo "Line: $line"
done < <(curl -s https://api.example.com/data | jq -r '.[]')

# Multiple inputs
paste <(cut -d',' -f1 products.csv) <(cut -d',' -f2 customers.csv)

Writing to Process Substitution

# Split output to multiple processes
command > >(process1) 2> >(process2)

# Tee to multiple destinations
echo "data" | tee >(process1) >(process2) >(process3)

# Log and process simultaneously
./script.sh 2>&1 | tee >(grep ERROR > errors.log) >(wc -l > linecount.txt)

#!/bin/bash
# Process two data sources in parallel

# Split pipeline into multiple outputs

curl -s https://api.example.com/data | \

Practical Data Processing Scripts

Example 1: CSV Filter and Aggregate

#!/bin/bash
set -euo pipefail

# Filter CSV by date range and compute statistics

input_file="${1:-transactions.csv}"
start_date="${2:-2024-03-16}"
end_date="${3:-2024-03-18}"

echo "Processing $input_file from $start_date to $end_date"

# Skip header, filter by date, calculate stats
tail -n +2 "$input_file" | \
while IFS=',' read date amount category; do
    if [[ "$date" > "$start_date" && "$date" < "$end_date" ]]; then
        echo "$date,$amount,$category"
    fi
done | \
awk -F',' '{
    sum += $2
    count++
    if ($2 > max) max = $2
    if (min == 0 || $2 < min) min = $2
}
END {
    printf "Count: %d\n", count
    printf "Sum: %.2f\n", sum
    printf "Average: %.2f\n", sum/count
    printf "Min: %.2f\n", min
    printf "Max: %.2f\n", max
}'

Example 2: JSONL to CSV Converter

#!/bin/bash
set -euo pipefail

# Convert JSONL to CSV with field selection

input="${1:-data.jsonl}"
fields="${2:-name,age,city}"

# Extract field names
IFS=',' read -ra field_array <<< "$fields"

# Print CSV header
echo "$fields"

# Process each JSON line
while read -r line; do
    values=()
    for field in "${field_array[@]}"; do
        value=$(echo "$line" | jq -r ".$field // \"\"")
        values+=("$value")
    done

    # Join with commas
    IFS=','
    echo "${values[*]}"
done < "$input"

Example 3: Streaming Calculator

#!/bin/bash
set -euo pipefail

# Calculate mean and median from streaming data

declare -a values=()
sum=0
count=0

while read -r num; do
    values+=("$num")
    sum=$(echo "$sum + $num" | bc)
    count=$((count + 1))
done < numbers.txt

# Calculate mean
mean=$(echo "scale=2; $sum / $count" | bc)

# Calculate median
IFS=$'\n' sorted=($(sort -n <<<"${values[*]}"))
mid=$((count / 2))

if ((count % 2 == 0)); then
    median=$(echo "scale=2; (${sorted[$mid-1]} + ${sorted[$mid]}) / 2" | bc)
else
    median=${sorted[$mid]}
fi

echo "Count: $count"
echo "Mean: $mean"
echo "Median: $median"

Example 4: File-Based Key-Value Database

This elegant example is inspired by Martin Kleppmann's "Designing Data-Intensive Applications" (Chapter 3). The entire database is just two shell functions and one text file:

#!/bin/bash

db_set() {
    echo "$1,$2" >> database
}

db_get() {
    grep "^$1," database | sed "s/^$1,//" | tail -n 1
}

How It Works

Write (db_set): appends a key-value pair as a new line to the file. That's it — one echo, one >>.

Read (db_get): searches the file for all lines matching the key, strips the key prefix, and returns the last match (which is the most recent value).

# Usage
db_set "name" "Alice"
db_set "city" "Berlin"
db_set "name" "Bob"      # overwrite: append new value

db_get "name"             # Bob (last match wins)
db_get "city"             # Berlin

The file after these operations:

name,Alice
city,Berlin
name,Bob

Advantages

Advantage Why
Blazing-fast writes O(1) — always appends to end of file, the fastest possible I/O operation
Simplicity The entire "database engine" fits in 2 lines. Easy to understand, debug, inspect
Crash-safe writes Append is atomic for small writes — no partial corruption of existing data
Natural history Every value is preserved — you get a built-in audit log for free
No dependencies Runs on any Unix system. No installation, no libraries, no daemon

Disadvantages

Disadvantage Why
Slow reads O(n) — grep must scan the entire file every time
Unbounded growth The file grows forever — old values are never removed (compaction needed)
No concurrency control Concurrent writes can corrupt data (>> is not guaranteed atomic for large values)
No data types Everything is a string. No integers, arrays, or nested structures
Comma in values If a value contains ,, the parse breaks — no escaping mechanism

Key Insight

This is essentially how log-structured storage works — the foundation of real databases like LSM-trees (used in LevelDB, RocksDB, Cassandra). The production versions add:

  • Indexing (hash maps, SSTables) to make reads O(1) or O(log n)
  • Compaction to merge old entries and reclaim space
  • Write-ahead logs for durability
  • Concurrency control with locks or MVCC

The lesson: append-only is a legitimate database design — not a hack. The simplest version already demonstrates the core trade-off of log-structured storage: write speed vs. read speed.

Best Practices

1. Always Use Quotes

# BAD: breaks on spaces
file=$1
cat $file

# GOOD
file="$1"
cat "$file"

2. Check Arguments

#!/bin/bash
set -euo pipefail

if [ $# -lt 2 ]; then
    echo "Usage: $0 <input> <output>" >&2
    exit 1
fi

input="$1"
output="$2"

3. Use Meaningful Variable Names

# BAD
f="data.csv"
n=$(cat $f | wc -l)

# GOOD
input_file="data.csv"
line_count=$(wc -l < "$input_file")

4. Add Comments

#!/bin/bash
# Process sales data and generate daily report
# Usage: ./process_sales.sh <input.csv> <output.txt>

set -euo pipefail

# Configuration
readonly MIN_AMOUNT=100
readonly DATE_FORMAT="%Y-%m-%d"

# Functions
filter_high_value() {
    awk -F',' -v min="$MIN_AMOUNT" '$2 >= min'
}

5. Use readonly for Constants

readonly API_URL="https://api.example.com"
readonly MAX_RETRIES=3
readonly TIMEOUT=30
